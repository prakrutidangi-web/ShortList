# Cold-start scorer: hand-weighted, UNTUNED; recency uses company-reported dates

**Status:** accepted

**Context:** Before labels exist the feed needs some ranking. Nothing may be claimed 'better' until Phase 3 measures it against recency-only, cosine-only and BM25 baselines. All postings from the first ingest share one first_seen_at, so a first_seen_at-based recency feature is meaningless for weeks.

**Decision:** Final score = 0.45 cosine (min-max normalized within the candidate pool) + 0.20 skill coverage + 0.15 seniority fit + 0.10 location fit + 0.10 recency, version 'untuned-v0'. These weights are a-priori guesses written in code and docs as untuned; the API response carries the weights version, a disclaimer, and a per-result breakdown (raw cosine, normalized cosine, skill coverage, seniority fit, location fit, recency) plus a request_id and 1-based position so Phase 3 impression logging can attach without changing the API shape. Recency = exp(-age/60 days) from source_posted_at (Greenhouse first_published / Lever createdAt, present on 100% of postings so far), capped at one year (older = 0, labelled 'possibly evergreen'). KNOWN LIMITATION: those dates can be stale or refreshed; once the daily ingest has run for a few weeks, 'new to us' (first_seen_at) becomes a separate feature. Unknown values are neutral (0.5), never penalties: missing skills, unknown location. Entry-level is a soft signal only (ADR 0011): seniority fit rewards 'entry', mildly favours 'unknown', and penalises 'senior'; interns are hidden unless the toggle is on; the entry-level and 'hide no-sponsorship' filters are user toggles, off by default. Same-title listings in other locations are merged into 'also listed in' (togglable) because about a third of postings are location variants of one role; repost groups are collapsed to one result. Retrieval pool: top 600 by similarity before collapsing; total_candidates is the pool size, not the number of matching postings.

**Alternatives:** Cosine only (that is a Phase 3 baseline); fitting weights now (no labels); Reciprocal-rank fusion with BM25 (decide after Phase 3 measures whether BM25 helps).

**Consequences:** Observed in a smoke run: a 'Product Design New Grad' role ranked 8th for an ML/SWE profile, because the profile text says 'new graduate' and there is no role-family fit term. The UI therefore offers 'only my target role families' (on by default) as a user-visible control; a role-family feature belongs in the learned ranker. Location fit is not country-aware ('Remote Canada' counts as remote).
